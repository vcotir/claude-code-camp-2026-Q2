Conclusions
* A fixed login process should be handled by a reusable script instead of being regenerated by the model.
* Coding harnesses may go off task and attempt to write unnecessary code.
* A dedicated MUD SDK or manager would provide a more reliable interface for connecting and sending commands.
* An MCP server could potentially expose that interface to a coding harness.
* Markdown files alone may not be sufficient for managing complex player and world state.
  * Key takeaway: Use coding harnesses for coding tasks. For a specialized operational agent, create a dedicated agent loop and reusable interface.
